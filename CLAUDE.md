# demonTD — agent notes

TouchDesigner operator for DEMON (real-time AI music gen over WebSocket).
`src/` is plain Python, unit-testable outside TD; `src/demon_ext.py` is the
only module that touches TD globals. The `.tox` is generated by
`build/build_tox.py` *inside* a running TouchDesigner (can't be built
headless).

## Protocol parity — the vendored contract is the reference

The DEMON backend is **self-describing**: `daydreamlive/DEMON`'s
`demos/realtime_motion_graph_web/protocol.py :: wire_contract()` is the
registry everything else is generated from (the TS SDK types, the live
`GET /api/protocol` endpoint). demonTD vendors that contract — plus the
web UI's parity data (canonical labels, config.json starting values,
the loraTriggers.ts blob SHA) — into **`vendor/demon_contract.json`**:

```bash
# re-extract from DEMON@origin/main (writes the artifact):
python3 scripts/sync_contract.py --demon ~/git/DEMON
# verify the committed artifact is current (exit 1 = stale):
python3 scripts/sync_contract.py --demon ~/git/DEMON --check
# the drift checker IS the test suite:
PYTHONPATH=src python3 -m pytest tests/test_contract.py
```

How parity stays closed-loop:
- **tests/test_contract.py** compares demonTD's real surface (wire.py
  encoders, events.py dispatch, session_config.py fields, params.py
  ranges/defaults/labels) against the artifact. Intentional gaps live in
  `contracts/parity_whitelist.json` — every entry needs a rationale, and
  hygiene tests fail entries that go stale or get implemented.
- **Runtime check**: at connect the op GETs the pod's `/api/protocol`
  off the main thread and surfaces vocabulary drift as a one-shot ⚠
  Status warning (src/contract_check.py). A stale .tox says so.
- **Nightly**: `.github/workflows/contract-sync.yml` re-syncs from
  DEMON@main, has a Claude agent draft the fix, and maintains one
  rolling PR (`contract-sync/auto`). Needs `DEMON_PAT` +
  `ANTHROPIC_API_KEY` secrets.

The sync script reads DEMON via `git show origin/main:<path>` — NEVER
the working tree. This is load-bearing: a working-tree diff of a
checkout parked on a stale feature branch once hid 23 commits of real
backend drift. `--ref <x>` reads another ref; there is deliberately no
working-tree mode. If DEMON restructures, the extractor exits loudly
naming every path it tried — fix the candidate lists at the top of
`scripts/sync_contract.py`.

demon-public-demo is no longer in the loop (it is itself just an rsync
mirror of DEMON's `web/` tree).

## Distribution — ship the bundle zip, not the bare `.tox`

The `.tox` loads vendored Python deps (`websocket-client`, `certifi`,
`zstandard`, `sounddevice`/portaudio) from a sibling `vendor/` folder at
runtime. A bare `demonTD.tox` with no `vendor/` next to it **fails to
load entirely** (`ModuleNotFoundError: No module named 'websocket'` →
`ws_client` won't compile → `demon_ext` import fails → extension never
instantiates). Always attach **`demonTD-vX.Y.Z.zip`** (`.tox` + `vendor/`)
to releases and tell users to keep them together. `zstandard` missing is
harmless (falls back to uncompressed slices); `websocket` missing is fatal.
`vendor/` also carries `demon_contract.json` — the baked-in contract the
runtime drift check compares against the live pod (missing = check
silently skips, not fatal).

## Release checklist

1. Bump BOTH `BUILD_MARKER` in `src/demon_ext.py` AND `DEMON_TD_VERSION`
   in `src/version.py` (the latter drives the `DaydreamDEMON-TD/<ver>`
   User-Agent).
2. `bash scripts/release.sh` (contract freshness vs DEMON@origin/main +
   pytest incl. contract tests) must pass.
3. Rebuild the `.tox` in TouchDesigner — confirm the boot `BUILD=` line
   matches, and that `dist/demonTD.tox` mtime is fresh BEFORE uploading
   (a stale `.tox` shipped once; always verify mtime).
4. Build the bundle zip (`.tox` + `vendor/`) and upload BOTH it and the
   `.tox` to the GitHub release.

## TD runtime gotchas (hard-won)

- **The `tick8ms` / `heartbeat` Timer CHOPs do not fire** in practice.
  `OnTick` and `OnHeartbeat` run off `frame_exec` fallbacks
  (`MaybeTickFromFrame` / `MaybeHeartbeatFromFrame`). Don't assume the
  Timer CHOP works; if you add periodic work, drive it from `frame_exec`.
- **The pod has no keepalive** — the only thing keeping its WS alive after
  `ready` is the continuous `params` stream. A dedicated **pacer thread**
  (`src/params_pacer.py`, ~16 ms cadence) sends it — NOT the frame loop —
  so TD main-thread hitches can't silence it (a >250 ms hitch used to eat
  the server's 0.25 s lead and chop the audio). It sends every tick, not
  just on change; an EMPTY params dict is still the keepalive, and it
  flows from `_connected` (pre-`ready` traffic is load-bearing — pods
  1011-idle-close during the initial VAE encode without it). Don't
  "optimize" it to send-on-change-only, don't gate it on `_saw_ready`,
  and don't move it back onto OnTick/frame_exec. The main thread
  supervises it from `_drain_inbound` (restarts it if dead, tears down
  on a send-fail streak).
- **Heartbeat + queue HTTP must stay off the main thread.** The
  `/api/queue/status` poll runs on `src/queue_worker.py`'s thread;
  `leave()` runs on fire-and-forget threads. Synchronous urlopen on the
  main thread (fresh TLS handshake, 10 s timeout, every 5 s) was the
  main "occasionally choppy" cause — it stalled params + slice patching.
- **The WS socket is single-threaded — keep it that way.** `ws_client.py`
  funnels ALL sends through an outbound queue drained by the recv thread,
  because Python's `ssl.SSLSocket` is **not safe for concurrent read+write
  from two threads** (it corrupts → `SSL: BAD_LENGTH` → client-side
  disconnect with no server error). Never call `ws.send()` / `ws.ping()` /
  `ws.close()` directly from another thread; enqueue instead. Don't re-add
  an app-level ping (that was a cross-thread write); the param stream is
  the keepalive.
- **`audio_out` cooks only because `frame_exec` force-cooks it**, and at
  audio rate only because of the `audio_clock` Wave CHOP carrier wired to
  its input. Don't remove either, or downstream Audio Analyze breaks.
- **TD can't programmatically hide a custom par** (`Par.hidden` is
  read-only). The `ui_hidden` flag in `params.py` means "don't generate
  it," not "hide it."
- **PortAudio `-10851`** = another op (an Audio Device Out CHOP) owns the
  output device. There is no "Preferences → Audio" device setting in TD;
  the fix is one-owner-per-device, not a pref.
